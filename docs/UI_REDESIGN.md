# React 前台与审核后台设计方案

状态：已实现并部署，2026-10-02 由 sol 团队完成。2026-10-02。依据用户决定，迁移时移除 Astro，前台采用 beUI，后台采用 shadcn-admin。参考依据与授权见 [UI_REFERENCES.md](UI_REFERENCES.md)。

## 统一技术与视觉基础

建议采用 React 19、TypeScript、Tailwind CSS 4、Motion、TanStack Router/Query。公开内容页需要服务端输出正文与 metadata，建议使用 TanStack Start 的 Cloudflare Workers 集成；它与 shadcn-admin 当前的 TanStack Router 技术方向一致，但管理页面仍需逐页移植，并非直接兼容的整包安装。[TanStack Start 官方部署说明](https://tanstack.com/start/latest/docs/framework/react/guide/hosting)、[shadcn-admin 依赖](https://github.com/satnaing/shadcn-admin/blob/main/package.json)。

前台和后台使用独立布局与按路由加载的代码，共享设计变量、基础组件和内容模型。后台编辑器/表格依赖不进入公开文章首屏；音频与 RSS 接口继续由 Worker 提供。现有 D1/R2 数据无需再次迁移，域名、文章地址、音频地址与两个 RSS URL 保持稳定。

公开阅读采用暖白底、炭黑文字、深绿主操作，播客辅色使用少量陶土橙。保留现有中文品牌“Agent 工作日志”。避免首页同时出现介绍框、部署说明和生成流程；只展示读者能阅读或收听的内容。

| 变量 | 建议值 | 用途 |
| --- | --- | --- |
| 页面底色 | `#FAF9F6` | 暖白阅读背景 |
| 表面色 | `#FFFFFF` | 控件、卡片和后台面板 |
| 正文色 | `#222C27` | 正文与标题 |
| 次要文字 | `#59665E` | 日期、时长、说明 |
| 品牌色 | `#245B45` | 播放、发布及选中状态 |
| 播客辅色 | `#B55B35` | 少量节目分类标识 |
| 边界色 | `#DDE3DD` | 分隔线和输入框 |
| 形状 | 卡片 16px、控件 8px | 前台柔和，后台紧凑 |
| 字体 | 中文系统无衬线，标题局部衬线候选 | 正文优先清晰，不依赖大字体包 |
| 正文 | 17–18px，行高 1.8，约 720px 宽 | 工作日志和 shownotes |

这些是设计起点；上线前对实际浅色/深色变量验收正文、禁用态和焦点对比度。状态同时有文字和图标，不只依赖颜色。

## 前台：现代编辑版式与持续收听

### 首页

导航：品牌、早咖啡、工作日志、归档；右侧搜索和订阅。移动端收成简洁菜单。主区域最大约 1120px，桌面两栏，手机单栏。

首屏左侧是最新一期：日期、实际时长、标题、一句话简介和“播放本期”。右侧是轻量节目视觉与章节概览，不放无关运营信息。没有新节目时展示最新可用期与真实日期；空库显示无节目状态。

下方独立展示最近节目列表和最新工作日志，工作日志以文字、日期和内容摘要为主。整张内容行可导航，播放按钮是独立操作，点击播放不触发导航。RSS 订阅提供播客/全部内容两种入口。

```text
Agent 工作日志                 早咖啡  工作日志  归档      搜索  订阅
────────────────────────────────────────────────────────────────
今日早咖啡 · 日期 / 实测时长        节目视觉与章节概览
标题与一句话摘要                   01 开场
[播放本期] [查看节目]               02 主线 / 03 短讯
────────────────────────────────────────────────────────────────
最近节目                           最新工作日志
日期 · 标题 · 时长 · 播放           日期 · 标题 · 摘要
────────────────────────────────────────────────────────────────
仅播放后出现：持续播放器 [节目] [−10] [播放/暂停] [进度] [+10]
```

### 节目详情与播放器

节目详情先显示标题、日期、时长和 AI 配音说明；正文包含主播放器、章节、节目内容与出处。桌面章节可位于侧栏，移动端成为清晰的章节列表。点击章节只 seek/play，页面与 URL 不跳动。

整个公开页面布局只拥有一个音频实例。React 根部保存音频控制器，节目卡片、详情控件和底部播放条只是不同控制入口。跨路由导航保留同一音频节点、时间、音量和播放状态。进入后台时先保留当前状态，管理界面不重复初始化音频；是否在后台显示控制条可作为后续产品设置。

大播放器位于普通文档流中，随原生滚动移动。离开视野后出现底部播放条；滚动触发交接直接跟随可见性，不做位置 spring 追逐。只有用户主动展开/收起时才使用共享布局动效。移动端底部条点击后打开可拖动 Sheet；拖动仅从把手启动，章节内容可以正常滚动。

采用 beUI 的 Button、Tabs、Bottom Sheet 和 Tooltip；复杂控件从源码适配后验收。Dynamic Island 只参考其紧凑展开的结构，不直接采用强弹跳、模糊与动态高度来驱动音频布局。[beUI 组件](https://beui.dev/components/motion)、[Dynamic Island](https://beui.dev/components/blocks/dynamic-island)。

### 工作日志与归档

工作日志采用单栏阅读版式：标题、日期、来源、摘要、正文和相邻内容。长文可有目录，目录导航与播客章节 seek 明确分开。正文链接、列表和代码块使用稳定排版。

归档提供“全部 / 播客 / 工作日志”、关键词和月份筛选；搜索只覆盖公开内容。beUI Tabs 负责选中标记，基础表单使用 shadcn/ui。搜索可先在小规模内容索引上实现，不把草稿混入前台返回值。

## 后台：人工确认工作台

采用 shadcn-admin 的侧栏、顶部栏、搜索、Data Table、表单和移动 Sheet，调整为中文。保留业务所需页面，演示项目的收入图表、客户、聊天、Clerk 认证样例不进入首版。

侧栏：**待确认、已发布、播客、设置**。登录后默认进入待确认，而非统计 Dashboard。待确认列表显示标题、来源、日期、状态和更新时间；支持搜索、筛选和“查看完整预览”，不提供批量确认发布。

### 审核详情

桌面左侧约 70% 为完整读者预览，右侧为确认卡、素材出处与修订信息。手机使用“预览 / 信息”两页签，底部操作栏留出安全区，不覆盖正文。确认卡显示标题、内容日期、拟公开地址和当前版本状态。

```text
侧栏          标题 / 待确认                           返回列表
              ┌────────────────────────┬─────────────────┐
待确认        │ 完整读者预览           │ 发布确认卡      │
已发布        │ 标题、摘要、正文       │ 标题 / 日期     │
播客          │ 来源链接与全部段落     │ 公开地址        │
设置          │                        │ 当前版本状态    │
              │                        │ 素材出处 / 修订 │
              └────────────────────────┴─────────────────┘
              [保存草稿]                      [确认并发布]
```

Beautiful UI 的 Approval Card、Context Cards、Diff Table 为参考：把“会公开什么”与对应动作放在一起。发布按钮直接确认当前所见版本，默认无需再弹第二个确认框。若预览未能加载完整内容、正在保存或版本已变化，确认按钮禁用并说明原因。[Beautiful UI](https://beautifului.dev/)。

确认 → 请求中 → 发布成功/失败是实际接口状态。成功后显示真实发布时间与公开链接，列表移入已发布；失败保留草稿，可针对当前版本重试。409 显示“草稿已更新，请重新查看”，加载新版本后需要再次确认。公开页面和 RSS 根据已发布指针更新。

首版不增加“退回修改”审批状态或编辑团队。代理返回的预览链接保持只读；操作者可以在后台修改并保存草稿，但保存产生新版本，仍需确认才能发布。发布审计来自真实 D1 记录。

### 播客与设置

播客页展示实际已经具备的数据：节目标题、日期、时长、公开状态、章节、页面与音频链接。制作任务进度只有在 Hermes 接入真实任务事件后才能展示；仅迁移 UI 时不绘制假的 TTS 进度或服务器状态。

设置首版包含站点外观、RSS 入口、审核登录和退出。提交密钥、审核密钥都不返回浏览器；保留独立凭据权限边界。站点外观当前来自构建配置，首版若提供修改入口，需要明确“应用更新后生效”；动态配置存储应作为独立后续改动。

## 三个有价值的动效

1. **持续播放器的主动展开与收起**：共享同一控制对象，视觉形态变化清楚，滚动路径保持原生响应。
2. **筛选与导航的选中变化**：Tabs 指示器、内容替换和移动 Sheet，让状态位置明确；避免每张内容行都重复入场。
3. **确认发布的结果反馈**：按钮 pending/success、短提示及列表状态更新都由服务器结果驱动，错误和冲突有可读文字。

建议交互反馈 120–180ms、布局/Sheet 180–260ms。滑块直接跟随指针，无额外 tween；播放进度更新只影响播放器局部，不让全站每帧重新渲染。默认不用模糊正文、磁吸按钮、滚动视差、连续 Orb 或逐字标题。`prefers-reduced-motion` 下去除位移，保留全部功能。Transitions 作为状态转换配方参考，统一用现有 Motion/CSS 执行，不引入第二套运行时。[Transitions](https://transitions.dev/)。

## 迁移实现顺序

1. 建立 React/Tailwind/TanStack 路由与共享变量；先复用现有数据模型和 Worker 发布服务，将 `astro/zod` 等依赖改成普通服务端依赖。
2. 移植公开页面、SSR metadata、RSS 与持续播放器，保持当前路径、章节行为和音频 Range 协议。
3. 移植 shadcn-admin 管理布局；为 React 后台补充真实的列表、读取修订、保存草稿、登录状态和版本确认 JSON 接口。当前后台主要是服务端 HTML，不能仅接一个模板就声称完成 API 对接。管理接口位于现有审核 Cookie 的路径范围内，提交凭据依然不能批准工作日志。
4. 接入选定 beUI 源码，逐组件审查 keyboard/focus/reduced-motion/触摸；按路由拆包。确认页与公开页复用同一个文章渲染器，保持 HTML 清洗。
5. 在隔离预览环境比较公开正文、RSS GUID/enclosure、草稿隔离、人工版本确认、跨页音频及手机操作；验证通过后再切换生产 Worker 并移除 Astro。

React 前台和审核后台已按上述方向实现，Astro 运行时已移除。内容继续使用既有 D1/R2 流程；部署与验收记录见本地迁移票据。
