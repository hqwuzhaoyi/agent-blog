# 编稿与产物结构

用日常问题开场，接具体例子与主话题，再给两三条短讯、编辑解读和思考式收尾。约800–1100中文字符、3–4分钟是常用目标，实际长度随素材与用户偏好调整。口播使用短句、自然过渡并解释必要术语，来源链接只放笔记。

个人体验标明是谁的体验；性能、容量与承诺保留条件。用“本期解读”标识节目自己的判断。解释用的类比明确是类比。使用独立节目名称和AI合成声明，避免让听众误认成来源节目或原主持人。

`episode.json`：

```json
{
  "title": "这一期的标题",
  "disclosure": "本节目为独立编稿与AI合成语音，来源观点归原作者。",
  "segments": ["完整句构成的开场段落。", "主话题段落。", "短讯段落。", "本期解读和尾声。"],
  "sources": [{ "topic": "原作者及内容", "url": "https://example.com/original" }]
}
```

每段使用完整句，通常60–110字；单句不超过120字。渲染时可能进一步按句子拆分，manifest 的 `section` 仍指向原始 segments 的下标。

`publication.json`：

```json
{
  "summary": "一两句节目简介",
  "chapters": [
    { "title": "开场", "section": 0 },
    { "title": "主话题", "section": 1 },
    { "title": "短讯", "section": 2 },
    { "title": "本期解读与尾声", "section": 3 }
  ],
  "materials": [
    {
      "url": "https://example.com/original",
      "summary": "用自己的中文概括这条来源的关键信息，并保留作者观点的归属与条件。",
      "chapterSection": 1
    }
  ]
}
```

选择4–6章，按实际段落顺序引用 manifest 中存在的 section。第一章包含开场；数字不是时间戳。章节校验脚本和博客发布器从实测时长计算时间，不接受估算。

公开 `shownotes.md` 包含开场钩子、本期内容、标注的编辑解读、编号来源与AI声明。私有 `notes.md` 另外保存音色、渲染过程、配乐署名和错误记录。成品 `episode.mp3`、干声 `episode.voice.mp3`、分段 WAV 和 manifest 保存在本期目录；公开发布只使用成品MP3和公开文稿。


## 本期素材卡片

完成选材后，为 `episode.json.sources` 中每个来源在 `publication.json.materials` 写一条中文整理，按节目叙事顺序排列。每条只含同一原文 `url`、1–3句 `summary`，以及能准确对应时的 `chapterSection`（引用上面已选章节的 section）。缺少明确章节对应时省略该字段。摘要说明素材的内容，不复制完整原文、转写或制作笔记。署名缺失时可用 `author` 补充快照中能确认的公开作者/机构名。

保留本期 `feed.json`。发布器仅从入选 URL 对应条目补齐作者、平台、原始发表时间和原题；缺失时间保持为空，不用采集日期冒充。频道或播放列表链接保留其真实类型，不写成精确单期链接。原始转写、未入选候选、社交计数与 feed 配置继续留在本地。

验收：dry-run 成功后，网页每个素材卡片都能回到原始链接；显示的摘要是中文整理，章节按钮对应实测章节。旧产物没有 `materials` 时，发布器兼容使用 `sources[].topic`，仅展示有证据的元数据，不猜章节。
