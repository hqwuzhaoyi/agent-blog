# 素材来源与新鲜度

默认读取 zarazhangrui/follow-builders 上游提供的三个 JSON：`feed-podcasts.json`、`feed-x.json`、`feed-blogs.json`。随附 `prepare-feed.mjs` 下载快照并保存更新时间和错误；该步骤不直接抓取原平台。

上游采集脚本使用播客 RSS 发现节目、pod2txt 获取转写、X API 获取近期原创推文，并从博客页面提取文章正文。维护在其 `config/default-sources.json` 中的配置包括播客、AI 构建者账号与官方博客。源列表会变化，以本期实际快照和当前上游配置为准，不把这里的说明当作实时采集结果。

区分 `fetchedAt`（本机下载时间）、各 feed 的 `generatedAt`（上游批次生成时间）、每条内容的 `publishedAt` 或 `createdAt`（原始发表时间）。早晨准时下载不意味着新闻刚发生，素材可以来自近期的周更访谈。

- 记录各类 feed 的更新时间，不用其中一个时间代替全部来源。
- 有内容但转写缺失、引用缺少上下文或文章正文为空时，跳过对应素材并记录错误；不得猜测。
- 采集整体失败时报告失败；成功但没有素材时报告无更新。部分来源失败时可以使用其余明确可用的内容。
- 原文链接用于来源归属，不代表已经独立验证原作者的主张。找到单期精确链接时优先使用；只有播放列表链接时标为播放列表，不伪装成单期链接。
- 本地重复执行同一批 feed 时避免重复选材，结合已有节目和来源 URL 去重。

直接采集、扩展来源或独立事实核查属于另一个工作分支，仅在用户明确要求时执行；本流程日常制作使用取得的快照。
